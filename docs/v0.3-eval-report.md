## 1. The question this run answers

The project's Cohere Labs blog was written on a **26K-sample** pilot and closed
on an open question, deferred to future work:

> *"How much training on the full 840K dataset is needed before translation
> quality emerges, not just language identity?"*

**v0.3 is that full-corpus run.** It trained the same Cohere2-LoRA + frozen-Moshi
architecture on the whole synthetic corpus for **2.07 epochs** over the
1,178,302-row train split (≈**2.9 epochs** over the 840,426 unique clips),
**2.44M samples · 6.59B tokens · 76,250 steps** on a single TPU v6e-16, WSD
schedule, zero preemptions. This report is the end-task answer.

**The answer, in one paragraph.** The text-pretrained backbone bet pays off, and
it pays off **data-efficiently**, but not uniformly: capability emerges in a
clear order — **language identity (early) → text translation (strong) → audio
synthesis (the remaining frontier).** Within ~3 epochs the model learns the
**translation mapping** in its text inner-monologue (teacher-forced token
accuracy 96.6%; free-run text chrF++ ~25) and produces target-language audio
that carries **genuine, if weak, translation signal** (BLASER-2.0 QE 2.5/5,
a reference-free speech-semantic score that is *higher* than the ASR-based
metrics imply). What has **not** yet emerged at this data/compute budget is
**intelligible speech synthesis**: the generated audio transcribes at chrF++
3.7–9.6 against a ground-truth-audio ceiling of 86–92, and its perceptual
quality sits 1.34 MOS below ground truth. The bottleneck is the **audio
codebook generation**, bounded by the frozen Moshi depth decoder — not the
translation understanding. v0.3 turns the blog's open question into a
quantified data-efficiency curve and a concrete next frontier.

## 2. Method

- **Harness:** [`scripts/eval_release.py`](../scripts/eval_release.py) — an
  8-stage resumable pipeline (generate → ASR judges → text metrics → MOS →
  semantic → LLM judge → latency → report). All numbers use the **corrected**
  autoregressive decoding loop (a pre-v0.3 off-by-one understated AR quality;
  see §7).
- **Subsets (frozen, digest-verified; loaders refuse on drift):**
  `v03-val-500` sha `91c7e2753e86a6a1…` (250/direction, in-domain);
  `v03-fleurs-200` sha `cd556805a9662662…` (100/direction, real human FLEURS —
  an **acoustic** domain shift only: 200/200 texts overlap the training corpus's
  FLORES slice, audited).
- **Decoding:** greedy (`--ar_temp 0`) for comparability.
- **ASR judges:** hi `vasista22/whisper-hindi-large-v2`, tr
  `openai/whisper-large-v3` (scores are **not** comparable across judges);
  `NORM_VERSION=hi-tr-v1`.
- **References are machine-translation-synthetic** — the corpus target text is
  MT-generated, so every absolute quality ceiling reflects that. **chrF++ is
  primary; BLEU is unreliable below ~5.** Every model ASR score is reported
  **next to the ground-truth-audio topline** (the same judge run on the GT
  target audio — the TTS+Mimi+ASR ceiling). MOS is reported as **Δ(gen − GT)
  only** (predictors are biased on codec speech).

## 3. Emergence — how quality appears over training (the centerpiece)

Two lenses, one training-step axis: **teacher-forced** validation (logged every
250 steps, the training-time signal) and **free-run end-task** evals (this
report's checkpoint sweep — the real generation).

![Emergence of translation quality over training: teacher-forced text accuracy
climbs to 96.6% and free-run text chrF++ to ~25 while generated-audio ASR-chrF++
stays low and BLASER-QE holds ~2.5 — language identity then text translation
emerge; audio synthesis is the remaining frontier.](assets/v0.3/emergence-curve.png)

**Teacher-forced trajectory (W&B `xzcb60bl`):**

| training step | 250 | 6,000 | 24,000 | 60,000 | 76,000 | first crossing |
|---|---|---|---|---|---|---|
| val text-token acc | 25.6% | 77.5% | 89.3% | 94.1% | **96.6%** | ≥50% @ 750 · ≥90% @ 27.5k · ≥95% @ 66.75k |
| val cb0 (semantic) acc | 10.4% | 34.5% | 38.3% | 40.2% | **41.5%** | ≥40% @ 51.75k, then **plateaus** |
| val composite (0.4·text+0.6·audio) | 6.72 | 3.94 | 3.07 | 2.92 | **2.82** | monotonic |

**Free-run end-task trajectory (this report's sweep, `v03-val-500`, greedy):**

| training step | 6,000 | 18,000 | 36,000 | 60,000 | 76,000 |
|---|---|---|---|---|---|
| free-run **text** chrF++ (hi→tr / tr→hi) | 14.8 / 13.3 | 19.7 / 18.5 | 23.3 / 21.1 | 23.5 / 23.6 | **25.7 / 25.1** |
| generated-audio **ASR-chrF++** (hi→tr / tr→hi) | 1.5 / 9.6 | 4.1 / 9.6 | 3.5 / 9.4 | 4.0 / 8.9 | **3.7 / 9.6** |
| **BLASER-2.0 QE** (hi→tr / tr→hi) | 2.36 / 2.42 | 2.44 / 2.43 | 2.49 / 2.45 | 2.48 / 2.49 | **2.53 / 2.49** |

Free-run **text** translation climbs steadily with training (direction-average
**14 → 19 → 22 → 24 → 25 chrF++**), the clearest evidence that the translation
*mapping* is what the full corpus buys. **ASR-chrF++ stays flat (~6 average)** and
**BLASER-QE inches up (2.4 → 2.5)** — the audio's weak semantic signal is present
early and barely moves: more data sharpens the text, not the synthesis.

**Reading the curve.** The **text inner-monologue** learns the translation
mapping fast and keeps improving to the end (TF accuracy crosses 90% by step
27.5k; free-run text chrF++ reaches ~25). The **semantic audio codebook (cb0)**
rises quickly then **plateaus around 41%** by mid-training — the frozen Moshi
depth decoder caps how well the coarse acoustic token can be predicted. The
**end-task audio** (ASR-chrF++) never leaves the floor: the model has learned
*what* to say (text) faster than *how to render it as clean speech*. This is the
data-efficiency finding — a text-pretrained backbone reaches translation
competence in the text stream within a few epochs, and audio-synthesis fidelity
is the capability that a larger data/compute (or an unfrozen depth decoder)
budget would need to move.

The **BLASER-QE 2.5** vs **ASR-chrF++ ~4** and **GEMBA 1.1** gap is the
informative nuance: BLASER embeds source and generated *speech* directly (no ASR

can recover. The generated audio is acoustically degraded rather than
semantically empty — consistent with the training-dynamics picture (every
codebook is alive; see below) and with the honest framing that **synthesis
fidelity, not translation understanding, is the gap.**

## 5. Checkpoint selection — `@best` ≈ `@final`; averaging does not help

All three release candidates are a **statistical tie** on the poor-audio axis;
weight-averaging (LAWA over the 66k–76k window) gives no gain and is *worse* on
tr→hi. Paired bootstrap (`src/evaluation/text_metrics.paired_bootstrap`, 1000
resamples, ASR transcripts vs references, per direction):

| candidate | hi→tr ASR-chrF++ | tr→hi ASR-chrF++ | text chrF++ | BLASER-QE | DNSMOS Δ | RTF | bootstrap vs `@best` |
|---|---|---|---|---|---|---|---|
| **`@best` (76,000)** — release | 3.7 | 9.6 | 25.7 / 25.1 | 2.53 / 2.49 | −1.34 | 0.95 | — |
| `@final` (76,250) | 3.8 | 9.8 | 25.9 / 24.8 | 2.52 / 2.49 | −1.35 | 0.93 | NS (p = 0.26 / 0.19) |
| LAWA (66k–76k avg, 11 ckpts) | 3.7 | 8.6 | 26.2 / 25.9 | 2.50 / 2.48 | −1.32 | 0.97 | hi→tr NS (p = 0.34); **tr→hi worse (p = 0.006)** |

→ **`@best` (step 76,000) is the release checkpoint.** `@final` is
indistinguishable; LAWA is rejected.

## 6. FLEURS — real-speech acoustic shift (winner only)

`v03-fleurs-200`, `@best`. ⚠️ **Acoustic shift only** — the texts overlap the
training corpus (200/200 via FLORES, audited); this is *not* a held-out-text
benchmark and must never be described as one.

| metric | hi→tr | tr→hi |
|---|---|---|
| free-run text chrF++ | 9.8 | 7.1 |
| generated-audio ASR-chrF++ | 1.2 | 9.3 |
| GT-audio topline chrF++ | 60.8 | 66.7 |

On real human recordings (re-encoded through Mimi) even the **text** stream
collapses to ~8 chrF++ (from ~25 in-domain), and the topline itself drops to
~61–67 — v0.3 is strongly **distribution-bound** to its synthetic-TTS training
acoustics. This is expected for a first full-corpus run on synthetic data and is
part of the honest picture.

## 7. Eight harness fixes found by running the evals end-to-end

The first full GPU eval pass surfaced (and fixed) eight defects — all in the
eval/reporting path, none affecting the trained weights:

| fix | commit | what it was |
|---|---|---|
| reproducible CUDA torch via uv conflicting groups | `ea05a9a` | eval box needs cu128 torch; captured in `pyproject.toml`/`uv.lock` |
| stage only the checkpoint bundle from the hub | `2608dff` | each branch mirrors the 51 GB suite; ignore it → 3.77 GB |
| Hindi Whisper judge empty `suppress_tokens` | `39bc2bf` | `suppress_tokens[-2]` IndexError on tr→hi rows |
| `ckpt_step` tolerates LAWA metadata | `5a6813b` | LAWA average has no scalar `step` |
| `load_checkpoint` tolerates LAWA metadata | `71a76ee` | same, in the model loader |
| normalize wavs for the BLASER SONAR encoders | `b887fd9` | 24 kHz / >1-amplitude wavs rejected → peak-normalize + 16 kHz |
| GEMBA `max_output_tokens` for gemini-3.x | `82d030e` | thinking model exhausts a 4-token cap → all scores null; raise to 1024 |
| isolate BLASER ref-mode | `fca3e23` | a corrupt SONAR text-encoder asset discarded the QE+cosine scores |

## 8. Reproducibility

Every pass wrote a `results.json` (schema v1) carrying: git SHA, checkpoint
step/revision, subset name+sha256, decoding {greedy, temp 0}, judge ids,
`NORM_VERSION`, metric-library versions, seed 1337. Eval box: uv `cuda`
dependency-group (torch 2.9.0+cu128); every command via
`evalpy () { uv run --no-default-groups --group cuda --extra eval python "$@"; }`;
Tier-3 semantic (BLASER/COMET) in a standalone `~/eval-sem` venv. References throughout are
MT-synthetic; FLEURS is acoustic-shift only; MOS is Δ-only; loss charts use
`train/audio_loss_full` (not the curriculum `train/audio_loss`).

> **Note on `/verify`:** the release does **not** claim a globally-green verify —
> a pre-existing lazy `torch_xla` import in `src/model/scan_utils.py` (TPU-only
> code, unrelated to this eval work) trips the stricter backend-seam gate; the
> module-level CI guard (`check_backend_seam.sh`) passes.
