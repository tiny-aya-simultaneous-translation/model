# TinyAya Stage 2 — Public Release Plan (v0.3, text+audio S2ST)

Goal: make **everything** public — models, all checkpoints, datasets, code, and an
honest writeup — so the project is a fully transparent, reproducible account of a
low-resource Turkish↔Hindi speech-to-speech translation attempt, including its
real data limitations. Honesty *is* the deliverable.

> **PREMISE CORRECTION (2026-07-08).** Everything below that says "audio-only /
> no text alignments" was based on a false verification: the check looked for
> legacy `_src/_tgt.json` filenames. The corpus actually ships
> **840,426 `.src.alignments.json` + 840,426 `.tgt.alignments.json`** (one pair per
> `.pt`, 100% coverage, real word-level `[word, [t0,t1], speaker]` content) at the
> repo/data root. The loader is fixed (`src/data/dataset.py::_resolve_alignment`) and
> **v0.3 trains text+audio** (`text_weight 0.2`) — a real translator attempt, not
> audio-only. Sections below are amended in place where load-bearing; the honest
> writeup should tell BOTH stories: the misdiagnosis and the correction.

> Status: drafted 2026-06-30; updated 2026-07-07. Recipe frozen + pipeline-validated;
> the full 3-epoch production run is **held** — before it launches, the recipe is being
> re-validated at a longer horizon on the full corpus (the original sweep ran only 1,500
> steps on the 200K subset with the per-CB accuracy metric broken). See
> [`v0.3-reval-sweep-plan.md`](v0.3-reval-sweep-plan.md) for the approved 6-arm
> re-validation → production → eval plan. The v0.3 model card waits on weights + eval.

## 1. The honest narrative (the spine of the release)

Three runs, one corrected story — tell it straight:

| Version | Data (actual) | Outcome | Honest note |
|---|---|---|---|
| **v0.1** | synthetic `tr-hi-mimi-encoded` (1.18M) | audio learned; **text stream did not** | We now know *why*: the corpus has **no text alignments** → the Moshi inner-monologue can't be supervised. |
| **v0.2** | `fleurs-tr-hi-mimi-encoded` (FLEURS, ~8.3k) | overfit (val bottomed @ step 1000) | Trained on the **wrong dataset** — the launcher's `HF_DATASET` defaulted to the `fleurs-` sibling. Disclosed on the card. |
| **v0.3** | synthetic `tr-hi-mimi-encoded` (1.24M) | **audio-only**, regularization-swept | The right data + the v0.2→v0.3 audio fixes (regularization, deep-codebook). Text is structurally absent (no alignments), so trained audio-only. |

**Key public findings (do not bury these):**
1. **CORRECTED 2026-07-08 — the corpus DOES ship per-sample text alignments.** The
   earlier "verified: 0 `_src/_tgt.json`" check used legacy filenames; the real files
   are `{stem}.src.alignments.json` / `{stem}.tgt.alignments.json` at the data root —
   840,426 of each, 100% coverage, real word-level content. Two stacked bugs hid them:
   wrong filename pattern in the check, and a loader (`_resolve`) that only looked in
   `encoded/`. With `zero_padding_weight=0.0` the failure was silent (text loss
   structurally 0). v0.3 is a **text+audio S2ST translator** (text inner-monologue +
   CB0 from the Cohere2+LoRA backbone, CB1–7 from the frozen Moshi depth decoder).
   The v0.1 "text stream did not learn" mystery is the same bug — worth its own
   paragraph in the writeup.
2. **Dataset attribution was wrong on v0.1/v0.2 cards** and is now corrected
   (v0.1 = synthetic but mislabeled "FLEURS"; v0.2 = actually FLEURS).
3. **Regularization sweep winner** (v0.3 overfit-regime, 200K subset, audio-only
   `val/composite` = `val_audio`): `lora_r=8, lora_dropout=0.15, weight_decay=0.10,
   lr_lora≈2.8e-4` — the most-regularized + higher-LR combo, i.e. the anti-overfit
   direction. This tuned the SMALL-data regime.
4. **Capacity sweep winner** (v0.3-SCALE, data-rich regime — full corpus, global
   batch 256, where overfitting is no longer the binding constraint, so the
   regularization-tuned recipe under-fits). **SUPERSEDED 2026-07-09 by the text+audio
   re-validation (`docs/v0.3-reval-report.md`): final recipe = arm D — the r32/+MLP/
   rsLoRA/lr 1.716e-4 base with `exclude_top: 0`; the exclude_top=2 champion below
   finished LAST on the text+audio objective.** Original two-stage sweep on the v6e-16:
   - **Stage 1 — structural grid** (which LoRA target modules), 3 arms to full 1500
     steps, rsLoRA on, `r=16`, `lr=2e-4`, `exclude_top=2`:

     | rank | `target_modules` | `val/composite` |
     |---|---|---|
     | 🥇 1 | `q,k,v,o + gate,up,down + embed_tokens` (**+MLP**) | **5.1326** |
     | 2 | `q,k,v,o + embed_tokens` (+attention) | 5.1539 |
     | 3 | `q,v + embed_tokens` (baseline, ~v0.2 structure) | 5.2164 |

     Clean monotonic trend — **more LoRA capacity → lower loss** in the data-rich
     regime, the opposite of the overfit regime's "regularize harder" answer.
   - **Stage 2 — Bayesian `lr × rank`** (W&B native sweep, method `bayes`), structure
     fixed to the +MLP winner, `lr_lora` log-uniform `1e-5…5e-4` × `lora_r ∈
     {8,16,32,64}`, rsLoRA on (`α=2r`). **Winner: `lora_r=32, lr_lora=1.716e-4`**
     (`val/composite=5.1189`), promoted to the production config
     `configs/tpu/stage2_tpu_v6e16_full_v03.yaml` (14,532 steps = 3 epochs).

## 3. Evaluation (must run before the v0.3 card is final)
Audio-only, so report what the model actually does — don't over-claim translation:
- [ ] **Per-codebook accuracy** (teacher-forced) on held-out val — CB0 vs CB1–7.
      Report with the **FIXED metric** (commit `8854698`): the earlier metric
      scored CB1–7 against the *undelayed* target while the model predicts the
      *delayed* codes, so CB1–7 read a false ~0%. CB0 (delay 0) was immune. See
      the correction note below.
- [ ] **ASR-BLEU** (Whisper transcribe generated target audio → BLEU vs reference) —
      expect low; report honestly (the model learns audio codes; sentence-level
      translation likely hasn't emerged, mirroring v0.1). NB: decode predicted
      codes with `undo_codebook_delay` first (eval_checkpoint fix `520b636`) —
      decoding the delayed predictions directly garbles the audio.
- [ ] **Use a loader-fixed checkpoint** — the TPU scan/grad-ckpt proxy saves backbone
      LoRA under a `layers.layers_list.<i>.layer.…` namespace; a vanilla eval model
      loaded **1/239** adapter tensors → backbone ran un-adapted → ~19% teacher-forced.
      Fixed (`eb17609`): `load_checkpoint` remaps the namespace (now 239/239, eval
      reconciles with training at **97.3% vs 98.1% CB0** on the overfit ckpt) and
      **raises** on any unfilled LoRA tensor. **Every prior `eval_checkpoint.py` number
      against a TPU checkpoint was invalid** (un-adapted); training dashboards were
      always correct (live model, not a reload).
- [ ] **Audio naturalness** (DNSMOS/UTMOS) on decoded Mimi.
- [ ] State protocol: checkpoint used (`best_by_val`), ASR backend+version, decoding,
      seed, #samples, text normalization.

> **⚠️ Correction — the "CB1–7 ≈ 0%" per-codebook accuracy was a METRIC BUG, not
> reality.** A prior note here claimed the delay-indexing was verified and
> "CB1–7≈0 is real, not a read bug." That was wrong: the val-loop accuracy
> compared predictions against `audio_codes` (**undelayed**) instead of
> `model_audio_codes` (**delayed**, what the model predicts and the loss trains).
> CB0 has codebook-delay 0 so it was correct (~98%); CB1–7 (delay 1–7) were
> scored against a misaligned target → pinned at ~random regardless of what the
> model learned. The **overfit / pipeline-validation gate** exposed it: on a
> 32-example memorization set CB1–7 *loss* fell to ~0.05 (≈95% conf.) while the
> metric still read ~0%. With the fixed metric the same run memorizes **all 8
> codebooks to 89–98%**. Fix: `train_hierarchical.py` (`8854698`); the model was
> always learning CB1–7 — every prior per-codebook accuracy (smoke runs, sweep
> leaderboards) understated CB1–7. Loss-based metrics (`val/composite`, the sweep
> rankings) were unaffected. True full-corpus CB1–7 *generalization* numbers to
> be produced with the fixed metric before the card is final.

      `sweeps/sweep_stage2_scale_bayes.yaml` (Stage 2).
- [ ] Sweep results, BOTH phases: the overfit-regime regularization sweep AND the
      v0.3-SCALE capacity sweep (Stage-1 grid leaderboard above; Stage-2 W&B bayes
      sweep — the native sweep dashboard is the artifact). ALL trial checkpoints are
      kept (`keep_last_n: 0`) under `gs://tinyaya-stage2-eu/checkpoints/stage2-scale-sweep/<run_id>/`.
- [ ] The winning recipe (capacity-sweep +MLP structure + Stage-2 `lr×rank`), written
      into the full-run config + the card.
- [ ] **Multi-host coordinated-sweep infrastructure** (`scripts/tpu/`) — a genuinely
      reusable learning worth open-sourcing: on a single v6e-16 the 4 hosts form ONE
      16-chip SPMD mesh, so a plain per-host `wandb agent` DESYNCS (each host pulls a
      different trial → mesh corruption). Two patterns solve it:
      - **Stage-1 grid**: a host-0 `sweep_coordinator.py` broadcasts each trial's args
        to all hosts via a shared GCS control file; deterministic run ids +
        checkpoint-truth completion make it idempotent/resumable across preemptions.
      - **Stage-2 bayes with the NATIVE W&B dashboard**: ONE `wandb agent` on host-0
        runs `sweep_agent_primary.sh`, which broadcasts the trial args to the 3 worker
        hosts (they form the mesh) AND runs host-0's PRIMARY training — whose run the
        agent creates INSIDE the sweep, so parallel-coordinates / param-importance
        populate. Workers attach to that one run via a GCS rendezvous.
- [ ] TPU engineering learnings worth documenting (part of the honest story):
      ephemeral `/mnt/data` on spot v6e (re-stage on preempt), the GCS-subset sweep,
      the audio-only pivot, and the control-plane failure modes hardened along the way
      (empty-env-var wandb crashes, stale GCS control state, `pkill -f` self-matches).

## 6. Durability / run hygiene (so the public run is clean)
- Training runs in **TPU-side `tmux train`** via `startup_script.sh` (workstation-independent),
  `--resume auto` for spot-preemption recovery, checkpoints to GCS.
- Pre-stage the full 1.24M corpus to GCS once (avoid 4M-file re-extract on every
  preempt) — same pattern as the sweep subset.
- **GCS bucket is `gs://tinyaya-stage2-eu` (europe-west4), co-located with the TPUs** —
  the old `gs://tinyaya-stage2-tpu` (us-central2) was deleted after every checkpoint write
  crossed region (cross-region egress was ~98% of the daily bill). Keep the bucket in the
  TPUs' region. Obsolete sweep/opt/v2 checkpoints were pruned (265 → 49.5 GiB); the v0.3
  run's own checkpoints are still kept in full (`keep_last_n: 0`).
